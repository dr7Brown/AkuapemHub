# AkuapemConnect FM Stations Module

## Objective

Add an **FM Stations / Online Radio** module to the existing AkuapemConnect platform.

The goal is to allow users to discover FM stations, open a dedicated station page, view the station's programmes and information, and listen to the station's live stream directly from AkuapemConnect.

## VERY IMPORTANT — REUSE THE EXISTING SYSTEM

This is an enhancement to the existing AkuapemConnect application.

**DO NOT rebuild existing functionality from scratch.**

Before writing code:

1. Inspect the existing project structure.
2. Identify the current authentication/user system.
3. Identify the existing admin dashboard.
4. Identify the existing database connection and database conventions.
5. Identify existing reusable components for:

   * cards
   * image/logo uploads
   * file/image storage
   * navigation
   * buttons
   * modals
   * forms
   * alerts/toasts
   * authentication
   * admin permissions
   * search
   * notifications
   * social links
   * advertisements/promotions
   * featured content
   * pagination
   * status/activation controls
6. Reuse those components wherever possible.
7. Follow the existing coding style, naming conventions, folder structure and database conventions.
8. Do not introduce a new framework, authentication system, CSS framework or database architecture unless the existing project genuinely requires it.
9. Do not duplicate existing tables or functionality.
10. Keep the implementation lightweight and mobile-first.

The final module should look and feel like a natural part of AkuapemConnect, not a separate application.

/fm/benkum-fm

Use the application's existing routing structure.

Do not create a separate routing system.

The station page should be visually attractive and mobile-first.

## Station Header

Display:

* station logo
* station name
* frequency
* location
* short description
* live status
* social links where available

Use existing UI components where available.

# 3. LIVE RADIO PLAYER

The most important feature is live streaming.

Display a prominent player near the top of the station page.

Example:

LIVE NOW

🔴 BENKUM FM

[ ▶ PLAY ]

[ 🔊 Volume ]

When the user clicks Play, the station's configured stream should play directly in the browser.

Use the HTML5 audio player where supported.

Example concept:

<audio controls preload="none">
    <source src="STREAM_URL">
</audio>

However, do not assume every station uses the same streaming technology.

The database should store the stream URL and stream type.

Possible stream types include:

* mp3
* aac
* m3u
* m3u8/hls
* icecast
* shoutcast
* other supported browser-compatible streams

If HLS requires a JavaScript player/library, check whether the existing project already contains a suitable library before adding a new dependency.

Do not unnecessarily install large libraries.

---

# 4. STREAM RESOURCE REQUIREMENTS

The AkuapemConnect server should NOT proxy, download, record or continuously relay the audio stream.

The browser should connect directly to the configured station stream whenever possible.

This is important because AkuapemConnect should not consume unnecessary server bandwidth.

The stream URL must therefore be treated as external media.

Use:

* `preload="none"`
* no automatic audio playback
* no continuous server-side audio processing

The stream should only begin when the user intentionally presses Play.

Create an "On Air Now" section.

* day of week
* current time
* programme start time
* programme end time

If no programme is currently scheduled, display something such as:

"Programme information unavailable."

Do not display false information.

# 12. SCHEDULE VALIDATION

Prevent obvious scheduling problems.

For example, warn the administrator if:

Programme A:
8:00 AM – 10:00 AM

Programme B:
9:00 AM – 11:00 AM

overlap on the same station and day.

Do not necessarily prevent saving unless the existing system normally uses strict validation.

Prefer a warning that allows the administrator to correct the schedule.

Handle programmes crossing midnight carefully.

---

# 13. STATION STATUS

Stations should have statuses such as:

ACTIVE
INACTIVE

Only active stations should normally appear publicly.

If a station is inactive, its public page should either:

* show that the station is currently unavailable, or
* return the application's existing not-found/inactive behavior.

Follow existing platform conventions.

---

# 14. LIVE STATUS

Do not pretend to know that a station is broadcasting unless the system can verify it.

There should be a distinction between:

"Station is active on AkuapemConnect"

and

"Station is currently broadcasting."

If reliable stream-status checking is not available, do not automatically display "LIVE" simply because the station record is active.

The administrator may optionally configure a station as:

* Live
* Offline
* Auto/Unknown

If possible, use a lightweight stream-status check without repeatedly consuming the stream.

---

# 16. SHARING

Use the existing AkuapemConnect sharing component if available.

# 17. SEARCH

Integrate FM stations into the existing search system if AkuapemConnect already has global search.

Users should be able to search:

"Benkum FM"

and find the station.

Do not create a separate search engine.

---

# 18. FEATURED STATIONS

If AkuapemConnect already has a Featured Content/Featured Listings system, reuse it.

Featured FM stations can appear higher in the FM section.

Do not build another independent featured system.

If the existing system does not support this type of content, implement the smallest possible station-specific solution.

---

# 19. ADVERTISING/PROMOTION

If AkuapemConnect already has advertising/promotional functionality, allow FM stations to eventually use the same system.

Do not build the advertising system as part of this initial FM implementation unless the existing architecture makes it trivial.

Prepare the station model so it can work with existing promotional functionality later.

---

# 20. MOBILE-FIRST DESIGN

Most AkuapemConnect users will access the platform using phones/tablets.

The station page must therefore be designed mobile-first.

Recommended order:

1. Station identity
2. Live player
3. On Air Now
4. Today's programmes
5. Weekly schedule
6. About station
7. Contact/social links

The player should remain easy to find.

Avoid unnecessarily large images or heavy animations.

---

# 21. VISUAL DESIGN

The FM station page should look modern and polished.

Use:

* station logo
* cover image
* rounded cards
* subtle shadows
* clear typography
* live indicator
* attractive play button
* responsive programme cards
* existing AkuapemConnect colors/components

Do not introduce a completely different visual identity.

If a station has a brand color, the page may use that color subtly for accents, but maintain AkuapemConnect's overall design language.

---

# 22. PERFORMANCE

This feature must have minimal impact on the existing platform.

Important:

* Lazy-load station cover images.
* Use existing image optimization functionality.
* Do not autoplay audio.
* Do not continuously poll radio streams.
* Do not proxy streams through the PHP server.
* Do not load heavy JavaScript unnecessarily.
* Load programme data efficiently.
* Use database indexes where appropriate.
* Reuse existing caching mechanisms if available.

---

# 23. SECURITY

Treat all administrator-entered fields as untrusted input.

Use the existing:

* authentication
* authorization
* CSRF protection
* validation
* escaping
* SQL parameterization
* upload security

Do not introduce insecure raw SQL queries.

For stream URLs, validate allowed URL formats/protocols and prevent dangerous schemes such as:

javascript:

data:

or other inappropriate protocols.

Do not allow arbitrary executable content to be uploaded as station logos/images.

---

# 24. EMPTY STATES

Handle cases where a station has:

* no logo
* no programme schedule
* no current programme
* no stream
* no social links
* no description

The page should still look professional.

For example:

"No programme schedule available."

"No live stream has been configured for this station."

Do not show broken images or empty UI elements.

---

# 25. ERROR HANDLING

If the stream cannot be played:

Display a friendly message such as:

"Unable to play this station right now. Please try again later."

Do not expose technical errors to normal users.

The administrator should be able to see useful diagnostic information where appropriate.

---
