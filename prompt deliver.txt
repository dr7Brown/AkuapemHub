# AKUAPEMCONNECT DELIVERY MONETIZATION MODULE

Enhance the Delivery Services Module with four monetization features:

1. Free Delivery Posting
2. Premium Rider Subscription
3. Verified Rider Badge
4. Sponsored Rider Listings

The system must be scalable, configurable by admin, and integrated into the existing user and wallet systems.

---

# FEATURE 1: FREE DELIVERY POSTING

## Purpose

Allow customers to create delivery requests at no cost.

## Rules

* No posting fee
* Unlimited delivery requests
* Visible to all active riders
* Standard priority

## Delivery Request Status

* Pending
* Accepted
* Picked Up
* In Transit
* Delivered
* Cancelled

## Display

Label:

"Standard Delivery Request"

---

# FEATURE 2: PREMIUM RIDER SUBSCRIPTION

## Purpose

Allow riders to subscribe for enhanced visibility and additional benefits.

## Subscription Plans

### Basic Rider

Price: Free

Benefits:

* Standard listing
* Can accept delivery requests
* No badge
* Normal visibility

### Premium Rider

Price: Admin Configurable

Examples:

GH₵20 Monthly
GH₵50 Quarterly
GH₵180 Yearly

Benefits:

* Appears before free riders
* Premium badge
* Higher search ranking
* Featured in rider directory
* Access to delivery statistics
* Priority access to new requests

---

## Premium Status Tracking

Store:

* Subscription Start Date
* Subscription End Date
* Subscription Status
* Plan Type

Automatic expiration required.

# DELIVERY REQUEST APPROVAL & APPLICATION WORKFLOW

Enhance the AkuapemConnect Delivery Services Module by introducing a mandatory administrative approval process for all delivery requests before they become visible to riders.

The objective is to eliminate fake requests, spam, scams, duplicate listings, and low-quality delivery postings.

---

# DELIVERY REQUEST CREATION FLOW

Customer Creates Delivery Request

↓

Request Status = Pending Approval

↓

Admin Reviews Request

↓

Approved OR Rejected

↓

If Approved:
Visible to Riders

If Rejected:
Returned to Customer with Reason

---

# RIDER VISIBILITY RULE

IMPORTANT:

Riders must NEVER see:

* Draft Requests
* Pending Approval Requests
* Rejected Requests

* Approved Requests
* Open Requests

# AUTO-APPROVAL PROCESS

If customer qualifies:

Request Status:

Approved

Immediately after submission.

No admin review required.

Admin can revoke privileges at any time.

---

# REJECTION WORKFLOW

If admin rejects request:

Customer receives notification.

Notification Title:

Your delivery request could not be approved. Please review the feedback and submit a corrected request.

Admin must provide rejection reason.

* Excessive posting frequency
